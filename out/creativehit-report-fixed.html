问题技术证据

!
▶ #01 首页 SSR 正文极度稀薄，可引用性实测为零 高
已确认 · 域名层 ← 返回行动清单
业务影响

首页是全站权重最高的入口，但 ChatGPT/Perplexity/Google AIO 抓取后没有任何一段可直接引用的文字来描述「CreativeHit AI 是什么、解决什么问题、给谁用」。AI 引擎只能依赖 title 与 meta description 的 50 字描述，被引用概率与引用准确度都显著降低；同时导致 homepage 在「AI 广告创意工具推荐」类检索中几乎无竞争资格。

证据

抓取首页（https://creativehit.ai/）实测：HTTP 200，正文 word_count=31 词，未检测到任何 H1 标签，可引用性扫描未找到任何 ≥20 词的内容段落（citability 平均 0 分，A/B/C/D/F 分段计数全为 0）。整页正文实际只剩导航与按钮文案：「开始创造」「创意模板」「创建工作流」「暂无相关模版」。

建议动作
负责人 · 内容

在首页 SSR 输出中注入 3–5 段静态文字段落（每段 ≥40 词）：① 一段「What is CreativeHit AI」定位段（产品定义 + 目标用户 + 核心能力）；② 一段「How it works」流程段（3 步流程，含可抽取的步骤实体）；③ 一段「Who it's for」用户画像段（广告营销团队 / 内容创作者 / 电商商家各一句）；④ 一段差异化对比段（与单发工具如 Midjourney、与设计工具如 Canva 的类别差异）。同时补一个语义化 H1（与 title 对齐：「CreativeHit AI - AI 广告视频与图片创意生成工具」）。

▶ #02 Organization schema 缺 sameAs，品牌实体无法与外部图谱对齐 高
已确认 · 域名层 ← 返回行动清单
业务影响

AI 模型无法把 CreativeHit AI 与 LinkedIn 公司页、YouTube 官方频道、Crunchbase 条目、Trustpilot 评价页等外部权威锚点绑定，品牌被识别为普通字符串而非稳定实体。在「最佳 AI 广告创意工具」「AI 视频生成工具对比」类答案中难以进入候选集；同时也无法被知识图谱聚合，实体消歧能力弱。

首页 JSON-LD 中的 Organization 仅包含 name=CreativeHit AI 与 url，sameAs 字段缺失（实测 0 条），同时缺 foundingDate、address、contactPoint 三个关键事实字段。通过 Wikipedia 与 Wikidata 官方 API 检索「creativehit」均无词条。

建议动作
负责人 · 市场

分两步：① 本周在 Organization schema 中补 sameAs 数组（至少 4–8 条真实存在的官方账号 URL，如 LinkedIn 公司页、YouTube 频道、X/Twitter、Crunchbase、Product Hunt、Trustpilot 等）。② 本月同步注册/认领上述平台官方账号并把已核验 URL 写回 sameAs。中期（1–3 月）积累 2 篇以上独立主流媒体报道后推进 Wikidata 词条。

▶ #03 Article.description 字段在全部采样文章页为空（模板级 bug） 高
已确认 · 模板层 ← 返回行动清单
业务影响

Google AIO 与 Perplexity 引用文章时优先读 Article.description；为空则回退到正文随机抽取，摘要质量不可控，且容易抽到「Back to app →」「More from the blog」等模板噪音文本。同时该字段缺失会让 Article schema 在 Rich Results Test 中触发警告。

证据

5 个采样文章页（/blog/ai-ad-creative-2026、/blog/ai-creative-workflow-platforms、/blog/workflow-automation-guide、/blog/ecommerce-product-visuals、/blog/whats-new-september）的 Article schema 中 description 字段全部为空字符串；对应 meta name="description" 仅重复标题（如「The State of AI Ad Creative in 2026 — CreativeHit AI Blog」），未提供正文摘要。

建议动作
负责人 · 内容

改文章页模板（一处修复全部 5 个页面）：在 Article JSON-LD 输出时把 description 字段填为正文首段前 150–160 字符的纯文本摘要（去除 emoji 与 markdown）；同步把 meta name="description" 改为同一段摘要而非重复标题。

▶ #04 Organization schema 缺 foundingDate / address / contactPoint 等关键事实字段 高
已确认 · 模板层 ← 返回行动清单
业务影响

AI 无法从结构化数据中抽取品牌创立时间、总部地点、联系方式等基础事实，知识图谱聚合度低；同时对 B2B/SaaS 类站点，contactPoint 缺失会被判定为「匿名运营实体」，E-E-A-T 信任分受损。

证据

首页 Organization JSON-LD 实测仅含 name 与 url 两个字段，缺 foundingDate、address (PostalAddress)、contactPoint (ContactPoint)。首页正文与页脚仅显示公司注册名「偉廸科技發展有限公司 GREAT TALENT TECHNOLOGY DEVELOPMENT LIMITED」，未提供结构化地址与联系方式。

建议动作
负责人 · 开发

在 Organization schema 中补：foundingDate（格式 YYYY-MM-DD 或 YYYY）、address（@type: PostalAddress，含 addressCountry / addressRegion / addressLocality）、contactPoint（@type: ContactPoint，contactType: customer support，email 或 url 至少一项）。这些字段需与页脚 / 联系页可见信息一致，不得编造。

▶ #10 缺 5 项安全响应头与 llms-full.txt，技术信任分有优化空间 低
已确认 · 域名层 ← 返回行动清单
业务影响
